# UI overhaul — 0.4

The main window now opens to compact Controls with one set of telemetry readings, four visible performance choices, fan mode and Cooler Boost. Fan curve contains the read-only graph and six bounded draft inputs. The Diagnostics tab, provider text panel and GUI export action are removed. Local diagnostic export through the existing command-line/API remains available.

The original Q/airflow icon has editable SVG and PNG assets plus a seven-size ICO. The executable, window, header and tray use it. Rebuild the raster assets with tools/New-AppIcon.ps1.

## Verification

The exact shipped UI sources are compiled into the native STA test harness. It exercises profile button clicks, explicit Apply/readback, boost and fan mode, all six curve bounds, exact session-original restoration, stale/suspended/failed reads, pending async operations, draft/focus/scroll preservation, Tab/Shift+Tab reveal, tray lifecycle, theme persistence, compact resizing and scaling.

Synthetic screenshots are generated by MainForm.DrawToBitmap in Light and Dark for Controls, Fan curve and a 440 × 600 pixel compact window. Fixtures are explicitly labeled Synthetic UI fixture and issue no live hardware requests. Actual desktop captures verify the native fan-mode and appearance dropdown arrows and open lists; DrawToBitmap alone does not accurately capture Windows' themed dropdown arrows.

The Windows desktop used for visual verification reports 120 DPI (125%). The layout also uses logical-to-device conversion for manual geometry. Moving between physical monitors with different DPI, a screen reader and Windows high contrast have not been independently verified.

    dotnet run --project tests/QuietMSI.UITests -c Release -- --smoke --screenshot artifacts/ui-overhaul/readonly.png

Current captures and their fixture/assembly/image hashes are in artifacts/ui-overhaul. Earlier .impeccable/review and dashboard review documents are historical 0.3 evidence.

The asynchronous test harness now restores the WinForms synchronization context after DoEvents. This keeps held-read continuations on the STA thread, matching Application.Run, instead of dispatching UI work onto a thread-pool thread. Production scheduling is unchanged.

No hardware write approval modes are needed for the UI checks; synthetic control requests stay inside the fixture. Normal hardware integration tests perform reads and rejected unsupported requests only.

## GPU temperature and borderless frame follow-up

When the verified MSI temperature getter supplies no GPU value, the telemetry worker now queries the existing driver-installed System32/nvidia-smi.exe with the read-only temperature.gpu query for adapter 0. It validates a single integer between 1 and 125°C, refuses N/A and unsuccessful exits, and stops the child on its two-second deadline or cancellation. Missing NVIDIA tooling leaves the value unavailable. No driver is installed, no PATH executable is trusted by the elevated process, and no hardware-control capability is granted by this fallback. GpuTemperatureSource records whether the displayed reading came from MSI or NVIDIA and is exposed in the GPU tooltip/accessibility description.

Reference: [NVIDIA's nvidia-smi documentation](https://docs.nvidia.com/deploy/nvidia-smi/index.html).

The frame now uses an integrated caption with minimize-to-tray, maximize/restore and close-to-tray actions. Native resize edges, dragging/snapping and taskbar-aware maximization are retained. Windows 11 gets rounded DWM corners and no colored border; cards/buttons use surface separation without outlines outside high contrast.

The full UI suite passed, including custom caption/maximize/restore/compact geometry. NVIDIA reader regression tests passed valid/invalid output, nonzero exit, missing executable, timeout termination and cancellation termination. The real unelevated sampler reported GPU 46°C from NVIDIA. The actual elevated app was opened on the desktop and its live UI reported CPU 56°C and GPU 50°C; no Apply action was issued.
